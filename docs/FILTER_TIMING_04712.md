# 0.47.12: フィルタ処理の追加軽量化と、入力条件別の時間超過

2026-09-25。0.47.11 の実機ログでも、MEKF・カメラによる足観測・制御は
30 秒間同時に動作し、FINISHED で終了した。検出できた足の範囲外は左右とも
0 件。前版で移した姿勢表示計算は軽くなったが、処理全体の超過率は増えている。
0.47.12 では比較用 Madgwick の角度取得と MEKF のコンパイル方針を見直す。

## 今回の実機結果

入力は `energy_control_autonomous_run_1_33554009.rwlog` と同名の足 CSV。

CSV の全 388 行が RWLOG 内の足観測と全フィールドで一致する。
原本は変更していない。出典ハッシュと集計値は

姿勢取り出しは約 33%、フィルタ全体は約 6.3% 短くなった。最大処理時間も
約 18% 減った。ただし超過回数は 120 回増え、平均処理時間も長くなっている。
**部分的な軽量化は確認できるが、全体の時間超過は解消していない。**
時間値は他タスクや割り込みによる中断を含む実経過時間であり、純 CPU 時間ではない。

取得・受け渡し・完了監査はそれぞれ異なる時点で数える。今回も取得数と
受け渡し数に 1 件の差があるが、取得故障・キュー取りこぼし・順序抜けは
記録されていない。開始・終了境界のカウント差と整合し、この集計だけで
全取得サンプルの個別配達を証明するものではない。
通常ログの最終 RUNNING 行は 30,001 ms。2,958 行すべてで MEKF が採用され、
制御 pitch・絶対 pitch・クォータニオン・比較用 Madgwick pitch は有限値だった。
終了スナップショットは指令 0 mA、実測 −2 mA、エラーなし。
この状態は書き出し時点のもので、停止直後の応答時間を示す値ではない。

## 足の範囲

計測中の右足は 291/293 有効、左足は 293/293 有効。右の無効 2 件は候補が
曖昧だったためで、範囲外による無効化ではない。開始・終了同期も含む全 388
フレームでは右 380、左 388 が有効で、検出済み範囲外はいずれも 0 件だった。

有効 X 座標は計測中、右 144.94550〜175.45181 px、左 139.88452〜174.24081 px。
右は旧上限 173 px を超える有効観測が 107 件あり、現在の右 [39,182] px の
範囲に収まった。左 [37,177.5] px も維持する。今回は範囲をさらに広げる必要は
なく、角度係数と起動ごとの独立ゼロも同じである。これは観測支持範囲の確認で、
移動する足を使って独立した絶対角度精度を検証したという意味ではない。
フレーム間隔からの観測速度は約 9.77 fps。

足を固定しない前後移動と足切り替え損失を踏まえ、振幅の非対称は今後の
制御改善に属する。同時動作の成功という評価を維持する。

## 追加修正

### Madgwick の pitch 取得

使用中の [Adafruit AHRS 2.4.0](https://github.com/adafruit/Adafruit_AHRS/tree/69fbb4021acbaccc55258ed8082d71c1968c8909)
の `getPitch()` は `computeAngles()` を呼び、roll・yaw・重力ベクトルまで求める。
本プログラムの比較系列はその pitch だけを消費していた。

公開 API の `getQuaternion()` から同じ値を読み、ライブラリと同じ式
`asinf(-2.0f * (x*z - w*y)) * 57.29578f` で pitch を取り出す。
これにより各取得から 2 回の `atan2` と使われない重力計算を除く。
追加の正規化や clamp は行わず、符号・非有限値・境界での挙動も元に合わせる。
Madgwick 自体の更新式、beta、更新周期、比較ログは維持する。

未変更の上流ソース 3 ファイルをテスト用に保存し、出典コミットと SHA-256 を
[`provenance.json`](../tools/fixtures/adafruit_ahrs_2_4_0/provenance.json) に記録する。
実機ビルドでは PlatformIO が実際に導入したファイルと照合し、相違があれば
ビルドを止める。テスト用の複製はファームウェアにリンクしない。

### MEKF の演算部分

`mekf6.cpp` の数値処理を、GCC のサイズ優先 `-Os` から速度優先 `-O2` に
切り替える。`no-fast-math` を明示し、式の近似・加算順序の変更・有限値だけを
仮定する最適化を使わない。共分散 36 成分、Joseph 更新、全軸の姿勢・バイアス、
補正と棄却の条件は同じである。変更範囲はこの演算ファイルに限定する。

これは実行コードの生成方針を変える修正であり、ESP32 での短縮量をホストの
ベンチマークから断定しない。次の実機ログで全体時間を評価する。

### 超過を入力条件別に記録

今回、フィルタ更新のうちパルス中の割合は 18.55% から 20.83% に増えた。
パルス中は高頻度ログ等の負荷が異なり、加速度補正が入る回にも負荷差がある。
これらは比較条件の違いであって、超過増加の原因を確定する証拠ではない。

そこで同じ 2.5 ms の完了監査を、制御処理に入る直前のパルス有無と、
受け渡された加速度が新しいかどうかの 4 群にも分ける。
`deadline_input_cohorts` に各群の件数・超過回数・平均・最大を保存する。
全体の件数と超過回数は 4 群の合計に一致する。
制御処理そのものの平均 `runner_mean_us` も、既存の集計値から出力する。
追加のタイマー取得やサンプルログ列の増加はない。集計の追加負荷も含めて
次回の全体性能を見る。

400/200 Hz のセンサ設定、1 ms のポーリング、I2C ドライバー、タスク配置、
全軸診断、カメラ、ログ周期、3 ms 補償、制御則、300 mA / 100 ms 上限、
10 ms の取得停止保護を維持する。完了監査の終了点と厳密な `>2500 us` の
超過条件も同じである。

## 検証と次の測定

- MEKF: ホストの `-O2` と `-Os` の各ビルドで、固定した旧実装との
  3,701,840 項目の数値比較が一致。予測 48,000 回、加速度更新試行 24,000 回、
  密な共分散 128 ケース、角度変換の境界・ランダム姿勢を含む。
- Madgwick: 未変更の上流 `getPitch()` と 22,059 ケースで一致。
  ±90 度付近・符号付きゼロ・非単位・非有限値も比較し、クォータニオンを
  変更しないこと、後から使う roll・yaw・重力 API への影響がないことを確認。
- 完了監査: 非計測・古いサンプルの除外、2500 us ちょうどと前後、時計周回、
  4 群と全体の整合、次の運転でのリセットを確認。
- 既存の取得・制御・停止・足認識・WebUI・RWLOG の回帰試験に合格。

[Web Flasher](https://temesotejam.github.io/atoms3r-free-foot-amplitude-control/)
の **0.47.12-filter-path-optimization** で同じ条件の 30 秒運転を行い、
RWLOG と足 CSV を保存する。主な評価は処理全体の超過率・平均・最大、
取りこぼし、足観測の継続であり、部分処理の短縮だけで達成とはしない。
