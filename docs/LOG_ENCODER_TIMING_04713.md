## 0.47.13 の変更

ログ 1 行の数値変換を `log_sample_encoder.cpp` に分離し、この関数に GCC O2 と
`no-fast-math` を適用する。int16 変換は同じ有限値判定・飽和・丸めのまま
インライン展開し、100 / 1,000 / 10,000 の尺度を呼び出し地点で定数として渡す。
各項目で繰り返していた小さな関数呼び出しをなくし、定数の処理を最適化しやすくする。
クォータニオンや角度の精度、欠損値、Q の変換式は同じ。

`ExperimentStatus` は内容を変えず専用ヘッダーへ移動し、変換器を単独検証できるようにした。
Roller の値は従来通り参照時計より前の一つのスナップショットを使う。
書き込みは同じ制御処理内で同期的に行い、停止時の確定・CRC・ダウンロード方式も維持する。
ログ周期（通常 20 ms、パルス中 2 ms）と全 258 バイトの行形式は変更しない。

既存の `log_row` 内に `log_encode` と `log_store` の時間計測を追加する。
前者は beta 上限の取得と変換、後者は PSRAM への `addSample()`。
既存の全体時間・完了期限には両方を含め、追加計測自体の負荷も次回実測に含まれる。
Roller スナップショット等は外側の `log_row` にのみ含まれる。

MEKF・Madgwick、全軸診断、カメラ、センサ周期、タスク配置、I2C、制御則、
3 ms 補償、300 mA / 100 ms 上限、取得停止保護は維持する。

## 検証

旧 0.47.12 のログ行組み立てを固定した参照と比較し、状態・同期イベント・時計周回・
欠損時刻・非有限値・飽和を含む 24,000 ケースで全 258 バイトが一致した。
丸め自体は既存の 2,548,692 比較でも検証する。
Xtensa 向けに生成した変換器オブジェクトでは、int16 変換用の関数呼び出しが消え、
残る数値ライブラリ参照は従来通りの Q 等で使う `lroundf` だけであることを確認した。
これらは互換性と生成コードの確認であり、実機の短縮量を証明するものではない。

[Web Flasher](https://temesotejam.github.io/atoms3r-free-foot-amplitude-control/) の
**0.47.13-log-encoder-optimization** で同様の 30 秒運転を行い、RWLOG と足 CSV を保存する。
次回は全体の超過率・平均・最大に加え、パルス中のログ変換と書き込みの内訳を見る。
