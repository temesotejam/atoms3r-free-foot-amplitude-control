# 0.47.21: 運転中の通信停止とログ回収

ユーザー承認の構成: 運転中はWeb STOPを必要とせず、機体側の姿勢STOPを使う。
制御時間2.5 ms以内の達成を優先し、足位置による損失・非対称性のモデル変更は行わない。
0.47.20の制御計算、MEKF、比較フィルター、取得周期、足校正、3 ms補償、
300 mA / 最大100 ms、5秒開始同期・30秒測定・5秒終了同期を維持する。
この版の無線復帰と時間超過の改善量は実機未確認である。

## 運転と通信

1. Webの開始要求を受け付け、202を返す。これは開始条件の最終成立とは異なる。
2. 350 ms応答待ちの後、既存TCP接続とHTTP待ち受けを閉じ、Wi-Fiを停止する。
3. AP停止イベントを確認してから制御担当へSTARTを渡す。停止失敗／2秒のタイムアウトでは開始しない。
4. 制御担当が直立・IMU・足観測などを再確認する。命令結果と、その後の状態発行の
   両方を確認して実行状態を判定する。5秒応答しないSTARTは取り消し、遅れて開始しないようSTOPを渡す。
5. 運転中はHTTP処理・表示取得を実行しない。通信担当の軽い終了確認は20 msごと。
6. 制御担当が終了／ESTOPに移り、RWLOGと足フレームへの追記を終了してから通信を戻す。
   開始と同じ制御周期でSTOPになった場合もログを確定する。
7. 新しいAP開始イベントの後、port 80の待ち受けを作り直し、待ち受け成功を確認する。
   失敗時はログを保持したまま通信側だけを再試行する。本体を再起動しない。

`esp_wifi_stop/start`で初期化済みのドライバーとネットワーク設定を維持する。
Arduinoのmode(WIFI_OFF)によるドライバー破棄と混在させない。
起動時の`WebUi::begin`、`logger.begin/clear`、`feet.begin`、`export.begin/reset`を
復帰経路で呼ばない。ルート登録、boot ID、観測バッファ、ゼロ点、転送tokenを維持する。

Web画面はPC側で再接続までの45秒の目安を表示する。運転の実測進行表示ではない。
開始応答が失われてもSTARTを再送しない。予定時間後に状態取得を再試行する。
PCが別のWi-Fiへ移った場合は同じSSIDへ戻す。運転中のページ新規読み込みはできない。
終了後は次の明示的STARTまでWi-Fiを維持し、ダウンロード待ちによる自動停止はしない。

## 姿勢STOP

既存MEKFの更新後、次の出力判断より前に判定する。
生IMUで確立した機体直立ベクトルをMEKF座標へ変換し、その方向への推定鉛直の
投影が0以下なら直立から90度以上の転倒としてSTOPする。前後両方向に加え、
横倒し・反転も対象。表示用pitchの範囲・ゼロ補正やEuler角の折り返しに依存しない。
追加フィルター、逆三角関数、長い静止待ちは使わない。

無効なクォータニオンまたは10 ms超の古い姿勢も停止理由にする。
停止は既存のモーター0 mA要求・パルス権限解除・ESTOP保持経路を使う。
物理出力への適用は既存Roller I/Oタスクが行うため、ソフトウェア要求と電源遮断は別である。
姿勢を戻しても自動再始動しない。待機中の校正・前後比較ではこの運転停止判定を動かさない。
90度判定は転倒を検出する条件であり、転倒前に止める条件ではない。

## USB診断とメモリ調査

起動ごとにOFF。Web診断欄またはUSBの `DIAG ON` / `DIAG OFF` / `DIAG STATUS`
で操作する。書き込みページにも明示的な選択を用意し、再接続時にその選択を再送する。
USB接続だけではONにしない。起動前の故障調査用に従来の8秒受信待機を維持する。

OFFでは周期的なRTC詳細サンプル、診断文生成・送信、スタック・ヒープ走査を止める。
軽量な受信待ち、起動段階記録、タスクの生存／段階値、制御期限の計測は維持する。
ONでも、運転準備から通信復帰までは全診断担当とカメラドライバーの走査を延期する。
Webのメモリ欄は時刻付きキャッシュのみを使う。未測定はsampled=false / 数値0。
通常のRWLOGと足CSVにUSB診断のONは必要ない。

## データ回収の不変条件

- 本体PSRAMの計測行と足フレームは、Wi-Fi停止中も記録する。
- 正常終了・姿勢STOP・既存IMU異常は同じ記録確定経路を通る。
- サンプルが1行以上ある確定ログを取得対象にする。開始前の失敗では空の測定を捏造しない。
- 既存の4 KBチャンク、同一token、チャンクCRC、全体CRC、ブラウザキャッシュを維持する。
- ログ準備／取得／中断後に通信を自動停止しない。破棄は明示的な次測定操作でのみ行う。
- 本体の電源断・再起動によるPSRAM消失は防げない。通信復旧に再起動を使わない。

## 検証範囲

ホスト試験では、APイベント待ち、開始拒否・タイムアウト・即時STOP、通信復帰失敗の
再試行、複数回の運転、時計の周回、USBの明示的ON/OFF、校正直立基準からの±90度と
yaw不変性を検証する。ブラウザ試験では運転中の定期GET停止、開始応答消失時の
再送防止、復帰失敗からの再開、ESTOP後の取得ボタンを検証する。

実際のC++シリアライザーによる最大イベント数＋768足フレームを実際のブラウザ
ダウンロード関数へ渡し、8,192 bytesで通信断を模擬する。保存済み2チャンクを再利用し、
残りを取得して全バイト・CRC一致、768行の足CSVを確認する。
これらはESP32の無線・実機の電源・PCのWi-Fi自動復帰を模擬した試験ではない。

実機では最初に1回の完走→同じSSIDへの復帰→RWLOG/CSV保存を確認し、
姿勢STOP後の保存、途中再取得、次回測定の保存も確認する。その後に5回の
時間計測を行う。2.5 ms予算と計測端点は変えず、超過数・最大値・欠落を比較する。
