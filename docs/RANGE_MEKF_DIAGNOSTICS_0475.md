既存の上限はそのまま。今回の4つの位置は範囲内となり、下限を越える別の位置は

## MEKFの全軸推定を診断に追加

通常の「診断JSONを保存」と「画像付き診断を保存」の両方に`mekf`オブジェクトを追加する。

| キー | 意味 |
|---|---|
| `roll_deg`, `pitch_deg`, `yaw_deg` | MEKF座標系のX・Y・Z回りのEuler角、degree |
| `quaternion.w/x/y/z` | 同じ推定姿勢のクォータニオン |
| `estimate: posterior` | 更新後の姿勢。未来予測・3 ms補償・測定ゼロ差し引き前 |
| `frame: mekf`, `euler_order: ZYX` | 既存MEKFの座標とEuler分解順序 |
| `valid` | 初期化済みで、全軸とクォータニオンが有限値 |
| `sample_us` | 最後に反映したIMU試料のホスト時刻。再初期化時はその時点のIMU時刻 |
| `age_us`, `fresh` | 取得時の経過時間。500 ms未満かつIMU正常をfreshとする |
| `yaw_reference` | `gyro_integrated_since_filter_initialization`。磁北基準の方位ではない |

`sample_us`は既存の32ビットマイクロ秒時刻を使用し、経過時間の計算は桁あふれに対応する。
初期化前は`valid=false`で、角度・クォータニオン・経過時間はJSONの`null`。
古い有効な推定値は値を保持して`fresh=false`とし、更新中と区別する。

Euler角とクォータニオンは、既に姿勢角を計算している箇所でまとめて取得する。
通常更新、起動時のバイアス推定後、測定開始前の再初期化のすべてで更新する。
HTTPは制御担当が発行した固定サイズのスナップショットを読むだけで、
フィルタ更新・追加のIMU読み出し・ネットワーク送信中のフィルタ参照は行わない。
追加のEuler計算を毎周期重ねず、従来計算していたroll/yawも捨てずに保存する。

画像付き診断には、その画像の受け取り時に読み取った制御スナップショットを固定する。
`mekf_time_semantics: control_snapshot_at_frame_delivery_not_exposure`と明記する。
画像をダウンロードした時点の最新MEKF値に置換することはない。
カメラ露光とIMU試料が厳密に同時という意味ではないため、校正用の比較では静止姿勢を使う。

従来のトップレベル`pitch_deg`とメイン画面は、状態に応じた基準・3 ms補償を使う
左右揺動用の制御角。新しい`mekf.pitch_deg`は補償前の姿勢角なので、同一値を要求しない。
フィルタ座標、ジャイロ係数、制御則、RWLOG v51の時系列レイアウトは変更しない。

## 確認

- 実測の直立・傾斜位置4件を角度計算へ入力し、すべて新範囲内になることと、元の角度値が保たれることを確認。
- 範囲の両端は範囲内、その直外側と従来の35 pxは範囲外になることを確認。
- 実際のMEKF実装へX・Y・Z回りそれぞれ20°の運動を入力し、対応する軸だけが20°になること、クォータニオンとの整合、取得によってフィルタ状態が変わらないことを確認。
- 初期化前、更新停止、IMU異常、時刻の桁あふれについて、実際のJSONを解析して確認。
- 画像更新後にも古いコピーのMEKF値が変わらないことと、診断保存に全軸が残ることを確認。
- 既存の`bash tools/test_runtime.sh`と、ESP32-S3ビルド・カメラタスクのリンク検証を公開前に実施。

実機では、更新後の通常診断JSONを直立時と前後傾斜時に保存すると、
左右揺動のpitchと、前後傾斜に対応する成分を比較できる。画像付き診断も併用できる。
