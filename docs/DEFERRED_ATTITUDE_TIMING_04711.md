# 0.47.11: 同時動作の継続確認と、姿勢表示計算の分離

2026-09-25。0.47.10 の実機ログでも、MEKF・左右の足観測・モーター制御が
30 秒間同時に動作し、FINISHED で終了した。検出できた足の範囲外は左右とも
0 件だった。一方、2.5 ms の処理時間超過は前回より減っていない。
0.47.11 は、制御に不要な表示角の計算を高頻度処理から移す追加修正版である。

## 実機ログの結果

入力は `energy_control_autonomous_run_1_42183521.rwlog` と同名の足 CSV。
RWLOG v51 の CRC は正常。CSV の BOM を読み取り時に扱い、真偽値表記・
数値文字列を正規化すると、足 CSV の 380 行は RWLOG 内の全フィールドと
一致する。原本は変更していない。ハッシュと集計値は
[`success_42183521_summary.json`](../tools/fixtures/success_42183521_summary.json)。

取得・受け渡し・制御完了の監査は異なる時点でカウントする。今回は取得の
30 秒目のビンに 1 件あり、制御ログの最終 RUNNING 行は 30,001 ms。
コード上、最後の制御処理中にも取得タスクは動き、状態の反映時点まで取得側の
計測は継続する。1 件差はこの境界の扱いと整合するが、個別サンプルの全配達を
この集計だけで証明することはできない。キュー取りこぼし・順序抜け・取得故障は
記録されていない。監査の境界を今回の変更で動かさない。

通常ログの RUNNING 2,797 行はすべて MEKF を採用し、制御 pitch・絶対 pitch・
クォータニオン 4 成分に非有限値はない。通常ログは全 400 Hz サンプルを
保存する形式ではなく、時間超過は別の全 fresh gyro 監査で数える。
終了スナップショットは指令 0 mA、実測 4 mA、エラーなし。
これは書き出し時点の状態であり、停止直後の応答時間を示す値ではない。

足は約 9.53 fps。右 4 件は候補の曖昧さ、左 1 件は形状判定で無効となった。
これを範囲内の有効観測に置き換えていない。今回の計測中の有効 X 座標は
右 140.96153〜172.56757、左 136.32495〜172.27719 px で、設定済みの
右 [39,182]、左 [37,177.5] px に収まる。今回の位置は旧範囲にも収まるため、
43 件から 0 件になった差のすべてを範囲拡張の効果とは解釈しない。
過去データの全包絡範囲を含むことは前版の再生検証で確認している。

足を固定しないことによる前後移動と足切り替え損失を踏まえ、振幅非対称は
今後の制御改善として扱う。同時動作の成功という評価は維持する。

## 残った負荷と今回の変更

0.47.10 で追加した内訳では次の実経過時間が記録された。

| 処理 | パルスなし平均 | パルス中平均 |
| --- | ---: | ---: |
| フィルタ全体 | 763.069 us | 851.801 us |
| MEKF 予測 | 196.801 us | 267.821 us |
| MEKF 加速度補正（実行した回のみ） | 382.623 us | 333.334 us |
| MEKF 姿勢取り出し | 150.146 us | 185.374 us |
| Madgwick 比較（実行した回のみ） | 113.139 us | 152.108 us |

加速度補正・Madgwick は 200 Hz、予測・姿勢取り出しは 400 Hz の設定であり、
各行の母数は同じではない。また、割り込み・他タスクによる中断を含み、
内訳はフィルタ全体に含まれる。平均をそのまま加算しない。今回の動き・
パルス中のサンプル数・追加した計測負荷も前回と異なるため、単独のコード変更が
悪化原因だと断定しない。観測された時間超過は改善していない、という結果である。

ソースを追うと、毎回の `captureMekfAttitude` は制御に必要な pitch のほかに
表示用 roll・yaw も計算していた。roll・yaw の直接の使用先は診断 JSON であり、
制御とカメラは保存済みの姿勢を受け渡している。

0.47.11 では、毎回の推定後に **全クォータニオン・バイアス・入力・時刻を
コピーし、制御 pitch だけを角度に変換する**。通常診断と画像診断を作る際に、
そのコピーから同じ ZYX 変換で全 3 軸を求める。制御経路から 1 更新当たり
2 回の `atan2` と roll・yaw の関連計算を除く。制御 pitch の正規化・clamp・
`asin`・単位変換は従来と同じ順序である。

HTTP は稼働中のフィルタを直接参照しない。画像保存後に本体が動いても、
その画像の診断姿勢と sample_us は保存されたままである。roll・yaw を間引いた
古い値と最新 pitch を組み合わせる処理でもない。全姿勢情報は各更新の
クォータニオンに保持される。MEKF の全共分散、全軸更新、400/200 Hz 設定、
座標系、Madgwick 比較、足観測、ログ周期、3 ms 補償、制御式、電流・時間上限、
停止保護を維持する。

プロファイルの版を `control_work_04711` とし、`mekf_attitude_scope` に
「事後姿勢コピーと制御 pitch、全表示角はコピーから要求時に算出」と記録する。
フィルタ全体と 2.5 ms 監査の開始・終了点は変えない。表示の変換は低優先度の
HTTP タスクで実行されるが、実機の割り込みやバス待ちを含む時間超過が
どこまで減るかは次の測定で確認する。

## 検証

- 固定した旧実装との比較: 48,000 回の予測、24,000 回の加速度更新試行、
  128 ケースの密な共分散。制御 pitch も毎回、旧 3 軸変換の pitch と厳密一致。
- 正規化前のクォータニオンについて、ゼロ・微小ノルム、符号反転、非単位、
  pitch ±90 度付近、ランダム姿勢の 4,145 ケースで pitch と全 3 軸を旧式と比較。
  上記を合わせ、3,701,840 個のスカラー比較が一致。
- 保存後にフィルタを動かしても、保存姿勢の診断 JSON が変わらないこと、
  3 軸表示・鮮度・時計の周回・無効値・画像と姿勢の対応を確認。
- 既存の制御・取得・停止・足認識・WebUI・RWLOG 書き出し試験を実行。

これらのホスト試験と実機向けビルドは、ESP32 での時間超過解消を証明しない。
次は [Web Flasher](https://temesotejam.github.io/atoms3r-free-foot-amplitude-control/)
の **0.47.11-deferred-attitude-display** で同じ 30 秒運転を行い、RWLOG と
足 CSV を保存する。主な比較対象は超過率・最大時間・フィルタ全体時間であり、
姿勢取り出し時間だけが小さくなったことで全体の改善と判断しない。
