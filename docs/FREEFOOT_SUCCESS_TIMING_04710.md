# 0.47.10: 足を固定しない同時動作の成功と、観測範囲・処理時間の改善

2026-09-25。0.47.9 の実機ログで、MEKF・カメラ足角度観測・モーター制御が
同時に 30 秒動作し、FINISHED で終了した。今回の統合実験は成功と扱う。
足を固定しておらず前後移動するため、足切り替え時の損失が増えるという
ユーザーの実機観察を踏まえる。終盤の振幅差は今後の制御改善の対象であり、
今回の同時動作を不成功とする理由にはしない。

## 成功ログと残った時間超過

入力は `energy_control_autonomous_run_1_32653719.rwlog` と同名の足 CSV。
RWLOG の CRC を確認済み。足 CSV の 391 行は RWLOG 内の足観測と、
真偽値・数値文字列を正規化して全フィールドが一致する。
ファイルの SHA-256 と集計値は
[`success_32653719_summary.json`](../tools/fixtures/success_32653719_summary.json)。

| 項目 | 0.47.9 実測 |
| --- | ---: |
| 計測時間 | 29.999910 s |
| 終了状態 | FINISHED |
| IMU 取得 / 受け渡し | 12,143 / 12,143 |
| キュー取りこぼし / 順序抜け | 0 / 0 |
| 受け渡し遅延 平均 / 最大 | 282.963 / 4,001 us |
| 取得から制御処理復帰まで 2.5 ms 超過 | 947 / 12,144（約 7.8%） |
| 同・平均 / 最大 | 1,514.268 / 6,884 us |
| 計測中の足観測 | 292 フレーム、約 9.73 fps |
| 右 / 左の検出成功 | 288 / 291 フレーム |

取得数と完了監査数は測定境界の対象が異なる。通常ログの最終 RUNNING 行は
30,001 ms であり、この 1 件差を IMU の欠落と解釈しない。
FINISHED の電流指令は 0 mA。終了状態のスナップショットは書き出し時点であり、
停止直後の遅延評価ではない。

この計測は全 400 Hz サンプルを通常行として保存するものではない。
処理時間は全 fresh gyro の監査、姿勢・電流は通常行とパルス中の高頻度行、
足観測は独立したフレーム列で評価する。ログの有効行では MEKF が採用され、
姿勢とクォータニオンの非有限値はなかった。

## 観測範囲を既存データ全体に合わせる

左右同定を改善した 0.47.4 以降の診断 6 ファイル、姿勢比較 JSON の個別画像・
時系列、3 回の RWLOG を使用した。片足ごとの valid な位置を採用し、
無効検出の数値や、それ以前の誤ったマーカー同定が疑われる診断は範囲決定に
使用しない。姿勢比較の平均値だけではなく、動かしている途中の観測も含む。
集計・出典ハッシュは
[`foot_range_20260925.json`](../tools/fixtures/foot_range_20260925.json)。

| 画像 X 座標 [px] | 右足 | 左足 |
| --- | ---: | ---: |
| 全採用データの最小 | 40.7181 | 38.7209 |
| 全採用データの最大 | 180.6437 | 173.52403 |
| 0.47.9 の有効範囲 | 40〜173 | 39〜177.5 |
| 0.47.10 の有効範囲 | **39〜182** | **37〜177.5** |

既存範囲と `floor(観測最小−1 px)` / `ceil(観測最大＋1 px)` の和集合を使う。
今回の 30 秒ログで右足が検出済みなのに範囲外だった 43 フレームも、
既存の比較データで範囲外だった有効観測も、すべて新範囲に含まれる。

これは既存の角度式を適用する観測範囲の拡張である。角度係数は
右 0.155146317、左 0.155496758 deg/px を使い、起動ごとの独立ゼロを保つ。
移動する足のデータから胴体角との一致を強制して係数を再推定しない。
角度を境界値へ切り詰めたり、無効な検出を有効化したりしない。
新範囲外は引き続き範囲外とする。元の支持範囲も独立定数として保存し、
拡張部の独立した角度精度を検証済みとするフラグは立てない。
WebUI、画像診断、RWLOG は同じ範囲定数を使用する。

## 処理時間を減らす変更

0.47.9 のフィルタ群はパルスなし平均 708.577 us、パルス中 798.605 us。
ログ 1 行はそれぞれ 264.228 / 334.746 us。値は割り込み・他タスクによる
中断を含む実経過時間であり、各処理の純粋な CPU 時間ではない。

1. **MEKF の固定長内積を展開**する。3 要素の内積のループ管理を減らし、
   同じ順序で同じ項を加算する。行・列は配列の型と境界を保って参照する。
2. **Joseph 更新の共通積を再利用**する。`r_eff * K[r][k]` は出力列によらず
   同じなので 18 個だけ求め、ソース上で 90 回の重複乗算を省く。
   共分散 36 成分、交差共分散、Joseph 形式、対称化はそのまま計算する。
3. **加速度ノルムを再利用**する。同じ入力の平方根をもう一度求めず、
   検査に使った値で各成分を割る。逆数乗算などへの近似変更はしない。
4. **ログの 16 bit 整数変換を軽量化**する。範囲制限後の整数部と小数部を
   使い、各フィールドの `lroundf` 呼び出しを置き換える。
   ±0.5 の単純加算では半整数直前の丸め結果が変わるので使わない。
   欠測値 −32768、飽和 ±32767、負数を含む中間値の丸め規則を維持する。

フィルタ内の MEKF 予測、加速度補正、3 軸姿勢取り出し、Madgwick 比較の
所要時間も個別記録する。既存のフィルタ全体時間に含まれる区間なので
これらを足し合わせて二重計上しない。時間計測自体の小さな追加負荷も含め、
次の実機ログで変更後の総時間を評価する。

IMU の取得順序・400/200 Hz 設定、MEKF の全軸、カメラ観測、Madgwick 比較、
ログ周期、3 ms 補償、制御式、300 mA / 100 ms、10 ms の停止保護、
2.5 ms の超過判定を保つ。後から監査終了点を前倒しして超過を隠す変更もしない。

## 検証と実機確認

- 固定した旧 MEKF 実装との比較で、48,000 回の予測、24,000 回の加速度
  更新試行、128 ケースの密な共分散を検証する。全共分散・姿勢・バイアス・
  診断値を含む 3,613,000 個のスカラー比較で数値一致を確認する。
- ログの整数変換は全半整数境界と直前・直後、符号、飽和、非有限値、
  ランダムな float ビット列で旧実装と比較する（2,548,692 比較）。
- 足の全採用データの包絡範囲、境界の内外、角度式・ゼロの独立性、
  無効検出の扱いを確認する。
- 既存の制御・取得・停止・WebUI・ログ書き出しの回帰試験と実機向け
  ビルドを行い、公開時にファームウェアの版とハッシュを照合する。

ホストでの一致・ビルド成功は、ESP32 上での 2.5 ms 達成を証明しない。
次は [Web Flasher](https://temesotejam.github.io/atoms3r-free-foot-amplitude-control/)
の **0.47.10-range-timing-optimization** で足を固定せず同じ 30 秒運転を行い、
RWLOG と足 CSV を保存する。比較対象は処理時間超過率・最大値・各処理時間、
取りこぼし、足の有効範囲であり、今回の振幅非対称を不合格条件にはしない。
