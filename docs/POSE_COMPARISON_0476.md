# 0.47.6: 静止姿勢の比較とyaw診断

対象: `0.47.6-pose-comparison`。前版: `8c26e1eaa0bc634222f7651da48db419773858a5` / 0.47.5。
2026-09-24の診断 `(8)(1)` / `(9)(1)` と、足を固定して胴体を前後に傾けたという確認に基づく。

## 今回の判断

| 項目 | 直立から傾斜への変化 |
|---|---:|
| MEKF roll | −20.434053° |
| MEKF pitch | +0.401411° |
| MEKF yaw | +8.446444° |
| 右足の胴体相対角 | +21.6173° |
| 左足の胴体相対角 | +21.0664° |
| 右相対角変化 + roll変化 | +1.183247° |
| 左相対角変化 + roll変化 | +0.632347° |

前後運動はrollに現れ、主制御・表示のpitchは左右揺動である。左右足の差は改善している。
一方、yawも変化しているので、残差をそのまま換算係数の誤差と断定しない。
実際のねじれ、ジャイロ残留バイアス、加速度補正を含む推定の変化、画像の投影・検出位置などは、
この2つの停止中JSONだけでは分離できない。2点に係数を合わせる処理は追加しない。

既存MEKF実装へ初期roll 1.881578° / pitch 0.544745°から、X軸の−10°/sを2秒、
静止2秒、+10°/sを2秒、静止2秒と入力し、対応する重力ベクトルで加速度補正した。
この理想入力では各時点のroll/pitch誤差とyawの絶対値は0.02°未満。
純粋な前後運動で8.45°のyawが必ず生じる計算ではないことを確認した。
実機のセンサ誤差、時刻、取り付け、三次元運動を再現した試験ではない。

## 実機での操作

1. 更新後、両足と胴体を直立させて起動時ゼロを確定する。30秒測定は開始しない。
2. 「前後傾斜と足角度の比較」の「直立基準を取得」を押し、約3秒静止する。
3. 足を地面に固定したまま、胴体を前後の片方向へ約5°、10°、15°、20°と傾ける。
   設定範囲内で、各段階に「この姿勢を追加」を押して静止する。角度は厳密に合わせなくてよい。
4. 約10°、直立へ戻した姿勢も追加する。往路・復路とゼロへの戻りを比較する。
5. 「比較JSONを保存」で `freefoot-pose-comparison.json` を保存する。各姿勢の最終画像も同梱される。

片方向とは直立からマーカーXが減少する、現在の使用範囲内の方向を意味する。
反対方向へ20°傾けることを要求しない。「検出画像を確認」の画像は最後に取得した姿勢で更新される。
ブラウザの再読み込みでこの比較セッションは失われるため、先にJSONを保存する。
保存した後は通常ポーリングの履歴追加を止め、次の姿勢取得で再開する。
「保存後に比較をやり直す」は保存操作後に利用できる。

## 表示と計算

基準からの差を次で表示する。

`残差 = (現在の足相対角 − 基準の足相対角) + (現在の胴体roll − 基準の胴体roll)`

足を対地固定し、同一軸・同一符号の前後平面運動をした場合、残差は0°が目安になる。
足の絶対対地姿勢を三次元で求めた値ではない。両足を実際に固定したかはソフトウェアでは保証できない。
比較用のroll/pitch/yawは保存クォータニオンを正規化して算出し、yawの±180°境界を折り返す。
rollはクォータニオンから得た上方向ベクトルのYZ投影角であり、単なる三次元回転角ではない。
加速度のYZ投影角変化もJSONに保存する。MEKFは加速度を利用するため、これは独立した角度校正器ではない。

基準とのyaw差>3°、取得中のyaw幅>1.5°、pitch差>2°、roll差>30°、左右どちらかの設定範囲外は
`planar_check=false` として「参考」と表示する。これらは今回の比較の選別閾値であり、校正精度の仕様ではない。
yaw差が大きい理由が実際のねじれか推定ドリフトかは、このフラグだけでは決めない。
足角度の係数、使用範囲、ゼロ点、MEKFの軸、制御計算は変更しない。

## 取得・品質・失敗時の扱い

- 1姿勢で800ms間隔の5つの `/vision/capture` メタデータを取得する。画像は最後の1枚だけを既存の
  最大4096BのCRC付きチャンク5個で転送する。通常の状態ポーリング周期は増やさない。
- 待機状態 `state_id=2`、左右有効、ゼロ確定、新しい画像とIMU入力を要求する。
  画像取得後の経過、撮影から受け取りの遅れ、IMUと加速度の経過は各300ms以内。
- バイアス補正後ジャイロノルム≤2°/s、加速度ノルムの1gとの差≤0.08gを各試料で確認する。
- 5枚の期間は2.5〜12秒。画像番号と時刻の更新を確認する。
  取得内のroll/pitch幅≤0.8°、左右各X幅≤3pxを要求する。
  yaw幅>1.5°は取得を拒否せず参考扱いにする。静止中の方位ドリフトも診断に残すためである。
- 基準は|roll|/|pitch|≤6°、左右各相対角の絶対値≤3°も要求する。
- 起動時乱数の `boot_id`、run ID、版、左右ゼロが異なる姿勢は混ぜない。
  古い画像・動き・通信・CRC失敗・中止は新しい姿勢を追加せず、取得済み基準と姿勢を保持する。
- 最大12姿勢＋基準。基準の暗黙の上書きはしない。転送中は開始・画像再取得等と排他し、STOPは利用可能。
- 状態ポーリングの履歴はブラウザ内に最大600件。古い履歴を除いた数を `trace_dropped` で記録する。
  これは約800ms間隔にHTTP処理時間を加えた標本であり、400Hzジャイロ積分のログではない。

上記は離散試料での静止確認であり、試料間のすべての動きを観測するものではない。
画像の露光とMEKFは厳密には同期しない。カメラ受け取り時点の制御スナップショットを使うので、
各姿勢を動かさず保持する必要がある。画像とともに保存する値を、後のライブ表示値で置き換えない。
実機で静止保持が難しく拒否された場合は、表示理由と通常診断または画像付き診断から判断する。

## 追加するIMU診断

通常診断と画像の `mekf.inputs` に以下を追加する。

| フィールド | 意味 |
|---|---|
| `valid` | 姿勢と加速度・ジャイロ・バイアスが有限値 |
| `frame: mekf`, `axis_order: xyz` | 3成分の順序。M5Unified生出力の軸ではない |
| `accel_g` | MEKF入力座標の加速度、g |
| `gyro_dps` | MEKF入力座標・Y感度補正後、MEKFバイアス差し引き前、degree/s |
| `gyro_bias_dps` | 同じ姿勢における更新後のMEKF推定バイアス、degree/s |
| `accel_sample_us`, `accel_age_us` | 加速度試料の時刻と経過、32ビットの折り返し対応 |
| `last_accel_update` | 最後の加速度補正の採否、信頼度、方向残差 |

gyroからbiasを引くと、このスナップショットの更新後バイアスで補正した角速度になる。
当該予測ステップで使った更新前バイアスとは厳密には異なる。
`last_accel_update` は最後の加速度補正試行の結果を保持し、ジャイロのみの更新を新しい加速度補正と数えない。
測定前の再初期化直後だけは、実際に用いた平均加速度と平均区間終端の試料時刻を保存する。
比較機能はこのSTART_SYNC状態を受け付けない。

HTTPは従来と同じ制御所有者が発行したスナップショットだけを参照する。
予測が拒否された周期には新しい入力を古い姿勢時刻に結び付けず、スナップショット全体を保持する。
足フレーム768件やRWLOG v51の時系列レイアウトは拡張せず、比較の画像と履歴はブラウザ内で保持する。
