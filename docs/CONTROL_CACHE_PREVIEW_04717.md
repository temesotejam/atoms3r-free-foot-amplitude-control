## 制御性能に対する扱い

**同じ入力に対する計算結果・選択パルス幅を維持し、重複計算だけを省く。**
近似式、入力の丸め、制御周期の低下、観測の間引きは導入しない。
ホストでの数値一致は実機の期限達成や運動の完全一致を証明するものではない。
処理遅延が変わればモータ指令が届く時刻も変わり得るため、
実機では超過数とともに振幅・左右差・出力幅を比較する。

### 同じ制御判断内の候補計算

各ゼロクロスに局所キャッシュを作り、同じ幅の予測電荷量と予測エネルギーを再利用する。
1回目の目標エネルギー探索と、積分補正後の2回目の探索は両方とも残す。
目標値に対する誤差、探索順、同点の扱い、上限・下限判定、無出力の特別候補はそのまま。
次のゼロクロスにはキャッシュを持ち越さない。

0～100 ms の101個の浮動小数点ペアと有効ビットで824バイト。
制御タスクの内部スタックに置き、動的確保や PSRAM を使用しない。
全ペアを毎回ゼロ埋めせず、16バイトの有効ビットだけ初期化する。
監査の eval_count は従来どおり論理的な候補評価回数で、
キャッシュヒットも含む。ログ形式と意味を黙って変更しない。

### 電流モデルの入力一致

予測到達電流は「指令電流の絶対値と実際に渡された電圧」、
立ち上がり時定数は「指令電流の絶対値」が一致した場合だけ再利用する。
モデル係数はビルド時の定数で、キャッシュは制御タスクだけが所有する。
電圧を整数化したキーや許容幅は用いない。
updatePulseModelPrediction が新しい電圧を取り込む処理とクランプを保ち、
1 float32 ULP でも入力電圧が変われば到達電流を再計算する。

### 計測中のプレビュー生成

WebUI は従来から計測中の画像取得を許可していないが、
カメラは毎フレーム160×120のプレビューを PSRAM に生成していた。
撮影前後の制御スナップショットのどちらかが実行中なら、この19,200画素の転記を省く。
START_SYNC・RUNNING・END_SYNC を含む。撮影・左右マーカー探索・足角度・
フレーム記録は継続する。制御タスクを待たせるロックは追加しない。

待機中の検出画像取得と姿勢比較は使える。最後の待機画像は、その元の時刻・
検出位置・姿勢と一緒に保持される。完了後はカメラ自体が停止する従来仕様のため、
保持画像は測定前のものになる。新しい画像はログ保存後に次の測定へ進むと更新される。
画像取得直前の走行開始など、タスク間の状態公開の境界で1枚の転記が重なる可能性まで
禁止する同期処理は追加していない。

## 検証

基準は commit 71623b3526ca46c2454584b8eb9bd9ebaa02bdd7。
凍結した計算式・探索コードは
[control_math_04716.json](../tools/fixtures/control_math_04716.json)、
実機の float32 入力は
[control_inputs_04716.json](../tools/fixtures/control_inputs_04716.json) に保存した。
テストは新しい実装の式と探索コードを直接取り出してコンパイルする。

- 実機入力208回の選択パルス幅は旧版・記録値とすべて一致。
  電荷量、エネルギー、誤差、飽和判定も旧版と一致。
- 論理評価9,152回に対して実計算4,253回。4,899回（53.5%）の
  電荷量・エネルギー計算を省略。時間の削減率ではない。
- 両方向・残留電流・積分補正・無出力を含む追加20,000件と、
  無効入力等300件でも旧版と一致。
- 電流・時定数は80,572組の入力で旧式と比較。
  繰り返し、符号反転、ゼロ、非有限値、電圧の最小刻み変更を含む。
- 計測中にプレビューの画像と付随姿勢を上書きしないこと、
  待機に戻ると新しい画像・情報の組へ更新できることを確認。
- 既存の MEKF、足検出・校正、全258バイトのログ、転送・CRC、
  停止優先、完了期限の境界といった実行系の回帰試験を継続。

    python3 tools/test_control_math_cache.py
    bash tools/test_runtime.sh

対象 ESP32-S3 のビルドでも、既存の IRAM 配置・ログエンコーダのサイズ・
カメラタスク配置の検査を継続する。M5GFX は、実際の0.47.16のビルドで
使用された0.2.30に固定し、古い0.2.25だった診断用表記を訂正する。
新しいライブラリへの更新を混ぜる変更ではない。

## 実機で次に確認すること

0.47.17 を書き込み、同じ8度目標・30秒で RWLOG と足角度 CSV を保存する。
可能なら同条件で複数回確認する。
比較対象は完了期限超過数・最大時間、通常パルス開始の solver と電流モデル時間、
足の有効率・範囲、振幅と出力幅。超過の集計端点と2.5 ms予算は変更しない。
校正範囲 R[39,182] / L[37,177.5]、MEKF と比較フィルタ、取得・ログ周期、
3 ms補償、300 mA・100 ms制限、10 ms stale ESTOP を維持する。

高優先度 IMU 読み取りの待ち方式、PSRAM への同期ログ保存、
カメラ探索と外部メモリ競合は残っている。今回の変更だけで期限超過が
完全に解消すると断定せず、実機結果を見て次の対策を選ぶ。
